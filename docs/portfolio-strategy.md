# Portfolio Strategy

## Recommended GitHub Setup

Start with this as the main pinned repository:

```text
company-it-service-platform
```

After this repo is stable, split or add smaller companion repos only if they are genuinely polished:

```text
it-knowledge-base-cms
m365-onboarding-automation-lab
```

The main repo should be the first public impression because it connects IT Support, full-stack development, and AI workflow skills in one realistic business context.

## Resume Positioning

### IT Support / Service Desk

Emphasise:

- Ticket triage and SLA awareness
- Microsoft 365, Teams, VPN, password reset, MFA, onboarding/offboarding knowledge
- Asset assignment and user support workflows
- PowerShell automation lab
- Documentation and troubleshooting runbooks

### Junior Full Stack Developer

Emphasise:

- React and TypeScript dashboard
- REST API design
- Shared typed models
- PostgreSQL-ready schema
- Validation and testing
- Clean repo structure and docs

### AI / Automation Junior Roles

Emphasise:

- RAG-style support workflow
- Knowledge retrieval and cited answers
- Evaluation cases and confidence scoring
- Future vector database path with pgvector
- Practical AI use case, not just a chatbot

## GitHub Profile Order

1. Pin `company-it-service-platform`.
2. Add a short profile README with target role and tech stack.
3. Keep assignment repos either private or clearly labelled as coursework.
4. Add screenshots and a 60-90 second demo video once the dashboard looks polished.
5. Keep commit messages professional: `feat: add ticket filters`, `docs: add m365 onboarding lab`, `test: cover copilot classification`.

## Practical Scope

Avoid building five half-finished projects. A stronger portfolio is:

- One strong integrated platform
- One smaller Microsoft 365 / PowerShell lab
- One optional legacy PHP/MySQL knowledge base later

The integrated platform should get most of the polish.
